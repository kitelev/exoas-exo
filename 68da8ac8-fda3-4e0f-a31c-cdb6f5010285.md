# exo__Enum

Superclass for closed-world enumeration classes. An instance of `exo__Enum`'s subclass is one of a finite, sealed set of named individuals — no new instances may be added at runtime, and enumeration members are pairwise disjoint by default.

## Semantics

- **Closed-world:** every member is enumerable at TBox-design-time.
- **Sealed:** new members require TBox change + migration, not runtime data.
- **Disjoint:** sibling instances do not overlap; classification yields exactly one match.

Compare to `exo__Asset` (open-world ABox individual): an enum subclass restricts both extensibility and identity semantics.

## Motivation (RFC 31c1a0be Phase 1 trigger)

Created to satisfy RFC 31c1a0be §"Предлагаемое решение" point 3 which requires `exocmd__SubstitutionToken` to subclass `exo__Enum (closed-world)`. The substitution-token set (`$target`, `$nowLocal`, `$now`, `$today`, `$todayStart`, `$targetFolder`, `$input`, `$value`) is fixed by the resolver implementation in `GroundingExecutor.substituteVariables`; new tokens require both TBox additions and a corresponding code change in the resolver — exactly the "sealed enumeration" pattern.

RFC ID: `31c1a0be-bc72-4a1e-8426-75e7b0ddedd2` (lives in vault-exodev/inbox/).

## Future use

Other plausible enum subclasses pending RFCs: `ems__EffortStatus` (currently modelled as a class with named instances, candidate for enum reification), `exocmd__Command_position` ("inline" / "menu" / "header"), `exocmd__Command_category`. Each migration would be its own RFC.
