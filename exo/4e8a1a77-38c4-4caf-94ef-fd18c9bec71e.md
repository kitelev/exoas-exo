The architectural layer this ontology belongs to. Range `exo__OntologyLayer`, cardinality 0..1 —
an ontology declares at most one layer; an absent value means the layer is not yet classified
(open-world, no default is assumed).

Read together with `exo__OntologyLayer_order` it makes the dependency direction checkable: an
`exo__Ontology_imports` or definition edge (range, domain, superClass, …) between two
ontologies is layer-conformant when it runs from a
higher `_order` to a lower or equal one. A violation means a foundation ontology has come to depend
on an application one — the cycle-prone direction.

The value is assigned by meaning (what the ontology is for), not derived from the import graph:
a domain vocabulary is `Domain`, a bridge between two domain vocabularies is `Adapter` (15).
`ontology-layer-derive.py` reads the assigned values and checks only the edge direction over
`exo__Ontology_imports` and the definition edges; `exo__AssetSpace_dependsOn` is not judged
(adapters share an assetspace with unrelated ontologies). RFC `14217015-963b-4020-b267-fd13b1275b3a`
§1, decision No. 7.
