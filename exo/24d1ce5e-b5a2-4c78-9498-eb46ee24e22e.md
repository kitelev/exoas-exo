# exo__Profile_includes

Список Spaces (библиотек — AssetSpace или FileSpace), которые user хочет видеть активными при этом профиле — прямые зависимости (Maven `<dependency>`). Per RFC 01a83de8 Phase 2 (retarget Ontology→AssetSpace from exo__FocusProfile_includes); range расширен до [[8f3e976a-2d6b-4fa4-9336-53aa01320e18|exo__Space]] per onto-RFC 18808c73 (D13) — FileSpace включается через subclass-closure.

## Semantics

- **Domain:** `exo__Profile`
- **Range:** `exo__Space` (subclass-closure: exo__AssetSpace + exo__FileSpace; существующие includes на AssetSpace валидны)
- **Cardinality:** 0..N (empty profile валиден — useful для minimum-load mobile mode где effective_set = только TS-floor)
- **Display name:** `includes`

Effective set вычисляется как `includes ∪ resolve(_imports parent)._includes` (MVP single-parent) per CQ2. Phase 4 — транзитивное замыкание `_imports*` + diamond dedup.

⛔ **UUID-form mandate:** значения `_includes` — только UUID-wikilinks (`[[<assetspace-uid>]]`). Label-form резолвится в literal → literal-safety guard молча обнуляет CQ-замыкание.
