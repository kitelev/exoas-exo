# exoas-exo — Exocortex core ontology AssetSpace

**The foundational meta-vocabulary for [Exocortex](https://github.com/kitelev/exocortex).** This repository is an **AssetSpace** — a git-backed package of vault assets you mount into an Exocortex vault. It defines the `exo` namespace: the universal asset model, the class/property meta-classes, and the structural concepts (ontologies, AssetSpaces, profiles, relations, queries) that every other AssetSpace builds on.

> **Where this fits.** Exocortex separates **the engine** (the RDF parser, SPARQL engine, layout renderer, command machinery — shipped as the plugin + `@kitelev/exocortex-cli`) from **the data it operates on**. `exoas-exo` is the **floor** of that data: it is always mounted (the "TS-floor"), because without the `exo` meta-classes nothing else resolves. See the engine's [Exo-as-SDK topology](https://github.com/kitelev/exocortex/blob/main/docs/explanation/assetspace-sdk-topology.md) — in that model `exo` is the platform's standard library.

---

## What's in here

A single namespace folder, `exo/`, holding ~200 UID-named Markdown assets: the core classes, their properties, and supporting individuals.

### Meta model — how everything is described

| Class | Role |
| --- | --- |
| `exo__Asset` | The universal root. Every asset in any vault is an `exo__Asset` (it carries `exo__Asset_uid`, `exo__Asset_label`, `exo__Asset_isDefinedBy`, timestamps, tags). |
| `exo__Class` | The meta-class for classes. A domain class (e.g. `ems__Task`) is itself an asset whose `exo__Instance_class` is `exo__Class`. |
| `exo__Property` | The meta-class for properties, refined by `exo__ObjectProperty` (links to assets) and `exo__DatatypeProperty` (literal values). |
| `exo__Ontology` | A namespace anchor (the `$ns` assets). Each AssetSpace namespace has one. |
| `exo__Namespace` | The namespace concept itself. |
| `exo__Prototype` / `exo__InstantiationRule` / `exo__ClassPrototype` | Templates + rules used to spawn new instances with defaults. |

### Structural classes — the SDK topology, as data

| Class | Role |
| --- | --- |
| `exo__AssetSpace` | A mountable git-backed package of assets. The descriptors in [`exoas-registry`](https://github.com/kitelev/exoas-registry) are instances of this class. |
| `exo__Profile` | A manifest selecting which AssetSpaces to mount. The `$$`-profiles in [`exoas-profiles`](https://github.com/kitelev/exoas-profiles) are instances of this class. |
| `exo__FileSpace` | A git-backed package of *files* (non-asset content). |
| `exo__Space` | The shared base of asset/file spaces. |

### Relations, queries, typed literals

- **Relations:** `exo__Relation`, `exo__Birelation`, `exo__NaryRelation` / `exo__NRelation` / `exo__TriRelation`, `exo__RelationType`, `exo__Statement` — first-class (reified) relationships.
- **Queries & views:** `exo__Query`, `exo__Collection`, `exo__Table`, `exo__Visualization`, `exo__BarChart`.
- **Typed literals & property kinds:** `exo__StringLiteral`, `exo__IntegerLiteral`, `exo__DateTimeLiteral`, `exo__Boolean`/`exo__BooleanProperty`, `exo__NumberProperty`, `exo__DateProperty`, `exo__TimestampProperty`, `exo__URLProperty`, `exo__UUIDProperty`, plus cardinality/schema helpers (`exo__PropertyCardinality`, `exo__PropertySchema`, `exo__SchemaOptionSet`, `exo__FrontmatterOrderSpec`).
- **Enums & functions:** `exo__Enum`, `exo__Function`, `exo__FunctionSignature` (+ input/output argument classes).
- **Lifecycle & deprecation:** `exo__DeprecatedClass`, `exo__DeprecatedProperty`, `exo__DeprecatedAsset` (+ migration-guide / replacement properties) — the homoiconic way to retire vocabulary without breaking back-references.
- **Identity & settings:** `exo__Person`, `exo__ExoIdentity`, `exo__AccessSession`, `exo__Setting`, `exo__SettingKey`, `exo__AppSettings`.

> Every class above is a live asset on disk in `exo/`. This README is reference prose; the authoritative definitions are the assets themselves.

## Using this AssetSpace

You don't clone this repo into your vault by hand — it is mounted through Exocortex, and because it is the TS-floor it is mounted automatically whenever you bootstrap a vault or apply any Profile:

- **CLI bootstrap:** `npx @kitelev/exocortex-cli bootstrap --vault ~/vault` mounts `exo` as the floor.
- **Profile apply:** `Exocortex: Apply profile` always keeps `exoas-exo` mounted (it is never unmounted — stripping it would leave the vault with no class definitions).

Once mounted, its namespace appears under `assetspaces/kitelev/exoas-exo/exo/` and the `exo__*` classes resolve in SPARQL, layouts, and commands.

## Conventions (for contributors)

- **UID-canon.** Every asset is a UUID-named file (`<exo__Asset_uid>.md`); the human label lives in `exo__Asset_label`. Wikilinks between assets are by UID.
- **Co-location.** An asset lives in the folder of the ontology its `exo__Asset_isDefinedBy` points at.
- **Meta vs super.** A class's `exo__Instance_class` is the *metaclass* (`exo__Class`); its `exo__Class_superClass` is the *parent class* (usually `exo__Asset`). Don't confuse the two.
- **CI.** Pushes run the shared [AssetSpace SHACL gate](https://github.com/kitelev/exoas-ci) (`validate schema --shapes-mode`).
