# exo__SettingKey_datatype (DEPRECATED)

⛔ **DEPRECATED 2026-09-19** (тикет `d72aba19`, решение фаундера «Полная миграция предиката»): заменено на [[fdb4d5e4-59b9-43d5-a25b-08126c0b28d7]] (`setting__SettingKey_datatype`). По RFC f402002b M1.1 `setting__SettingKey` — кросс-источниковый каталог ключей, а `exo__SettingKey` ⊑ `setting__SettingKey` наследует его предикат; 23 инстанса `exo__SettingKey` переведены на `setting__SettingKey_datatype` в том же коммите. Писателей нет; runtime-читателей нет (`VaultSettingsRegistry` — TS-зеркало; unit-тест плагина парсит старое имя из submodule `packages/exoas-exo` — follow-up-тикет на regex + бамп submodule). `exo__Property_minCount` снят, чтобы мигрированные инстансы не краснели по этой форме.

Историческая семантика (до deprecate): объявленный тип значения ключа настройки. Per onto-RFC 981b6070 (D23).

## Semantics

- **Domain:** [[a37d39ec-413d-4d9c-8cf2-da9b6025b00c|exo__SettingKey]]
- **Range:** string-literal enum — допустимые значения ровно `boolean` | `string` | `stringList`. Литералы (не individuals): RFC 981b6070 §Новые классы декларирует ровно 2 класса, range задан как enum {boolean,string,stringList} в lowercase-токенах; minimal TBox-footprint — аргумент выбора granular-модели. Code-coercion в settings-loader (RFC Phase 5) читает literal напрямую.
- **Cardinality:** была 1..1 (REQUIRED); после deprecate — 0..1, обязательность живёт у преемника `setting__SettingKey_datatype`.
- **Display name:** `datatype`

Схема валидных настроек + их типы живут В ГРАФЕ (CQ3): `?key a exo:SettingKey ; setting:SettingKey_datatype ?dt` (прежняя форма `exo:SettingKey_datatype` пуста после миграции).
