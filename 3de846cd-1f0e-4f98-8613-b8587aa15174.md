# exo__FocusProfile

User-declared subset of ontologies for runtime RDF-graph activation. Per RFC b6ba5595 (lives in vault-exodev/inbox/).

## Semantics

FocusProfile прескриптивно описывает «какие онтологии user хочет видеть активными» — отличие от descriptive meta-organization classes (Ontology, AssetSpace, AssetSpaceArchitecture, Dependency).

Plugin lazy-loads RDF только для assets с `isDefinedBy ∈ effective_set(activeProfile)`.

## Disjoint with (per Noy-McGuinness §4.2)

- `exo__Ontology` (UID `829b9b3b-6fc3-4276-be6a-27d3398c012e`) — namespace declaration (descriptive)
- `exo__AssetSpace` (UID `73bd00e4-ccc0-4f3f-b20d-c4388c4588fb`) — storage container (descriptive)
- `exo__AssetSpaceArchitecture` (UID `11c35658-776a-4df5-b723-0292d6db0f36`) — file-format vocabulary (descriptive)
- `exo__Dependency` (UID `aa701e0d-c9f7-4b6e-95b2-9a63034ebf33`) — semver-bound coupling (declarative)

Один инстанс не может быть одновременно FocusProfile и любым из них — разные семантики (prescriptive vs descriptive).

## Properties

- `exo__FocusProfile_includes` — declared ontologies to activate (0..N, range exo__Ontology)
- `exo__FocusProfile_extends` — parent profile to inherit (0..1, range exo__FocusProfile, max depth 5)
- `exo__FocusProfile_alwaysOnOverlay` — overlay ontologies always loaded regardless of includes (0..N, range exo__Ontology)
