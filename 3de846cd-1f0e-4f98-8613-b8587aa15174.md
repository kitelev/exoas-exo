# exo__Profile

User-declared subset (BOM — bill of materials) of AssetSpaces for runtime RDF-graph activation. Per RFC 01a83de8 (Phase 2; renamed from exo__FocusProfile per RFC b6ba5595).

## Semantics

Profile прескриптивно описывает «какие AssetSpaces (библиотеки) user хочет видеть активными» — отличие от descriptive meta-organization classes (Ontology, AssetSpace, AssetSpaceArchitecture, Dependency).

Plugin lazy-loads RDF только для assets, чьи AssetSpaces ∈ effective_set(activeProfile). Профиль = BOM поверх AssetSpace-библиотек (Maven-аналогия: `_includes` = прямые зависимости, `_imports` = parent POM).

## Disjoint with (per Noy-McGuinness §4.2)

- `exo__Ontology` (UID `829b9b3b-6fc3-4276-be6a-27d3398c012e`) — namespace declaration (descriptive)
- `exo__AssetSpace` (UID `73bd00e4-ccc0-4f3f-b20d-c4388c4588fb`) — storage container (descriptive)
- `exo__AssetSpaceArchitecture` (UID `11c35658-776a-4df5-b723-0292d6db0f36`) — file-format vocabulary (descriptive)
- `exo__Dependency` (UID `aa701e0d-c9f7-4b6e-95b2-9a63034ebf33`) — semver-bound coupling (declarative)

Один инстанс не может быть одновременно Profile и любым из них — разные семантики (prescriptive vs descriptive).

## Properties

- `exo__Profile_includes` — declared AssetSpaces to activate (0..N, range exo__AssetSpace) — прямые библиотеки
- `exo__Profile_imports` — parent profile to compose (0..1, range exo__Profile, single-parent MVP; transitive 0..N → Phase 4)
